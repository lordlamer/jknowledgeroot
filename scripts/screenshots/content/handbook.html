This handbook collects how we work: how new colleagues get started, how we review code and how a release leaves the building. It is a living document. If something is wrong or missing, edit the page and leave a comment.

How we work

  • Small changes, often. A pull request should be reviewable in one sitting.
  • Tests travel with the change. A fix without a test is a fix we will make again.
  • Write it down. Decisions live in Architecture decisions, procedures in Runbooks.

Working agreements

Nobody merges their own change without a second pair of eyes, including the maintainers.

Core hours are 10:00 to 15:00 CET. Outside of them, asynchronous communication wins: write in the ticket, not in a direct message.
